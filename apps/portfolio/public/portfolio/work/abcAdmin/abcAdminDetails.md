# ABC Admin

2024.04 - current

## 서비스 내용

---

미국 법인 서비스(모니터링, OMS, WMS, 작업 관리, 내부 시스템 관리)를 제어하는 어드민 시스템.

- 주문 관리 시스템
  - 고객이 주문한 제품을 관리하는 서비스입니다. 고객에 대한 정보, 제품 정보 등 확인하고 관리할 수 있습니다.
- 물류 관리 시스템
  - 네코아의 제품(정수기, 매트리스, 공기청정기, 자재 등)을 관리합니다.
  - 재고관리, 창고 간 제품 이동, 발주, 출고, 입고 등 물류 전반적인 시스템을 관리할 수 있습니다.
- 테크니션
  - 테크니션이 어느 위치, 시점에서 일하는지 일정을 확인하고, 관리자는 작업을 배정할 수 있습니다.
- 시스템
  - 공통 코드 관리, 권한관리 등의 서비스를 제공합니다. 또한 넷마블의 챗봇 연동이 되어 직원들에게 업무 가이드를 보다 편리하게 제공합니다.

## 기술스택

---

- React, Typescript, TanStack Query, Recoil, Mui, Emotion, Sentry, Vitest, Vite, AWS EC2

## 개발내용

---

**서비스 개발**

- WMS의 출고, 창고이동, 창고 및 테크니션 재고실사/조정/재고추적 등 화면 신규 화면 개발
- 기획 요청에 대해 적극적으로 조율, 효율적인 화면 구성을 제안하여 불필요한 개발 이슈 및 지연이슈 해결

**렌더링 이슈 및 코드 최적화**

- 기획, BE, FE 팀과 협력하여 BE API 구조와 호출 순서를 최적화
- **불필요한 API 호출 구조를 개선하여 최대 3,000ms에 달하던 지연 시간을 최대 1,000ms 로 단축**
- **API 호출 순서 및 Lazy loading과 Suspense, 컴포지션 패턴을 활용 FCP 개선**

**개발 생산성 증대**

- FSD, Composition 아키텍처를 사용하여 코드 유지보수성 강화
- **50개 이상의 화면에서 공통으로 사용되던 컴포넌트를 ‘react-hook-form’ 기반의 단일 템플릿으로 통합하여 개발 기간을 단축하는데 기여**
- SNB, Details 공통 화면 모듈화를 통한 코드 복잡도 최소화
- query params 기반의 API 호출 제어

**Sentry를 활용한 에러 트래킹**

- Sentry를 통해 스테이징 환경에서 발생하는 타입 에러 및 비정상적인 API 호출을 검출,
- Jira에 기록하고 팀 내에서 신속히 공유함으로써 에러 수정 시간을 단축.

**개발 문화 개선**

- 프로젝트의 코드 컨벤션을 수립하고 적용하여 코드 일관성을 확보
- GitHub 코드 오너 추가 및 PR 리뷰 프로세스를 도입하여 코드 품질을 개선
- husky, commitlint를 활용하여 컨벤션에 부합하지않은 코드의 푸시를 방지하는 프로세스 개발
- 기획자가 개발 환경에서 직접 피드백을 줄 수 있는 기능을 개발하여 팀 간의 협업 효율을 높임

**Example 페이지 개발**

- 기술 적용 전, 기본 동작 예제 코드를 작성하여 팀 내 비슷한 기능 사용 시 참고할 수 있도록 하여 신규 기능 학습 시간 단축

**Google Sheets 연동 개발**

- 개발 및 스테이징 환경에서 기획자가 즉각적인 피드백을 제공할 수 있도록 Google Sheets와 연동하여 기획 및 개발 간의 커뮤니케이션 창구 생성

## 성장경험

---

1. `openapi`를 활용하여 개발 시간 단축.
   1. `openapi-typescript` 를 사용하여 타입을 BE가 제공해주는 yaml 파일을 변환하여 사용하므로, 타입 작성 및 변환하는 시간을 단축할 수 있었습니다.
   2. FE, BE의 enum 코드를 맞추어 코드를 일관성 있게 사용할 수 있도록 했습니다. BE가 잘못 내려주거나 오타 등 같이 확인할 수 있어 상호간의 코드 품질을 높일 수 있었습니다.
2. FSD 디자인 패턴 경험
   1. 대메뉴(OMS, WMS, 테크니션, 모니터링, 대시보드 등)와 하위 중메뉴들을 관리할 수 있는 아키텍처가 필요했고, 이에 FSD 패턴을 적용하였습니다.
   2. 컴포넌트 및 훅 유닛 테스트가 용이하도록 컴포넌트를 구성할 수 있었습니다.
   3. 유사한 템플릿을 갖추고 있어 최대한 공통 컴포넌트로 추출하는 개발 방식 적용하였고, 이를 공통 개발 방식 룰셋으로하여 개발 속도를 향상시킬 수 있었습니다.
3. 테스트 코드
   1. util함수와 컴포넌트, 훅에 대한 테스트코드를 작성하여 코드의 안정성을 높이려 했습니다. 그 결과 stg에서 발생하는 지라 이슈를 줄일 수 있었습니다.
4. 다양한 메뉴 개발
   1. WMS, 테크니션, 회계 및 기타 시스템 관련된 기능을 개발하며 다양한 도메인에 대한 견문을 높일 수 있었습니다.
   2. 기획과 개발자간의 빠른 소통으로 더 나은 UI/UX를 제안하고 피드백 받으며, 서비스의 품질을 보다 높일 수 있었습니다.

## 트러블 슈팅

---

**Situation**

1. 서비스 안에서 사용되는 공통코드 간 관계를 설정하는 N:N의 관계성을 잇는 화면 개발 요구.
   1. 관계 코드를 추가할 때 마다 새로운 객체를 생성하는 함수형 프로그래밍을 기반하여 설계.
   2. 화면 설계를 recoil의 selector를 활용하여 개발 진행.
   3. 화면 리렌더링 성능이슈가 발생하였고, 세분화한 recoil selector로 인해 소스 분석 어려움.

**Task**

1. 설계의 근본적인 문제점 파악
   1. react hook form과 연관된 리렌더링 이슈 및 매 이벤트 발생 시, 화면 렌더링에 따른 성능이슈 원인 분석

**Action**

1. 설계 방식 변경
   1. 커스텀 hook을 만들고 js 동적 바인딩(얕은복사)을 통해 리턴된 객체에 children을 초기화하는 방식으로 설계 변경.
   2. 재귀 함수를 활용하여 children에 따른 node 객체 생성.

**Result**

1. 얕은복사를 이용한 설계로 성능이슈를 해결하였고, 재귀함수사용 및 커스텀 훅으로 변환하여 비즈니스 로직 파악을 보다 쉽게 설계함. 테스트 코드를 작성함에 있어서도 이전보다 수월하게만듬.
