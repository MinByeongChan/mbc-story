# 배정 어드민 시스템

2022.10 – 2024.04, 2026.01 – 현재

## 서비스 내용

---

작업자, 일정, 이관과 배정 현황을 지도·목록·캘린더로 확인하고 조정하는 코웨이 내부 운영 도구입니다.

- 서비스 매니저가 작업자의 현재 위치와 배정 현황을 실시간으로 모니터링합니다.
- 작업 현황 확인, 작업 이관, 담당 구간 설정 등 배정 운영에 필요한 기능을 제공합니다.
- 지도, 목록, 캘린더 세 가지 뷰로 같은 배정 데이터를 다른 관점에서 확인할 수 있습니다.

## 기술스택

---

- React, TypeScript, Zustand, Recoil, TanStack Query, Naver Map, react-big-calendar, Datadog RUM, MSW, Vitest, Storybook

## 개발내용

---

**초기 구축 (2022)**

- Naver Map 기반 마커, 폴리곤, 범례, 툴팁을 개발하고 지도와 목록 사이의 상태와 상호작용을 연결했습니다.
- 수천 개 단위 마커 렌더링 병목을 분석해 지도·목록 상호작용 시 표시 기준과 렌더링 범위를 조정했습니다.
- `react-big-calendar` 기반 주간/월간 작업자 일정 화면을 개발하고 타임슬롯과 작업자별 배정 가능 시간 UI를 커스터마이징했습니다.
- datepicker, 폼 컨테이너, selectbox, searchInput 등 공통 컴포넌트를 Storybook과 함께 구축했습니다.
- 서비스매니저 이관 화면의 체크 리스트 이관 로직(useChecks)과 활동조 노출 로직을 개발했습니다.
- MSW 기반 목 데이터로 API 의존도를 낮춘 개발 환경을 구성했습니다.

**전국 실시간 모니터링 고도화 (2024)**

- 조회지표 테이블의 셀렉터를 리팩터링하고 정렬 기능을 추가했습니다.
- 배정건수 그래프 산정 로직을 다시 잡고, queryString 기반 검색과 윈도우 탭-테이블 링크 연동을 개발했습니다.
- 수치가 바뀔 때 숫자가 올라가는 넘버링 애니메이션 카운터를 개발했습니다.
- 이후 자동조회 타이머 버그를 수정하고 지도 메모리 누수를 해소해 반복 조회 속도를 개선했습니다.

**지도 메모리 누수 제거**

- **DevTools Heap Snapshot으로 지도 조회를 5회 실측해 조회당 약 290개씩 누적되던 detached DOM을 확인했습니다.**
- **지도 인스턴스를 싱글턴 방식으로 전환해 반복 조회 시 detached DOM이 0개로 유지되도록 개선했습니다.**

**상태 관리 구조 마이그레이션 (Recoil → Zustand)**

- 유지보수가 중단된 Recoil의 수십 개 Atom과 Selector를 분석해 기능별 Zustand Store로 재구성했습니다.
- 서버 상태와 자동 새로고침은 TanStack Query로 분리하고, 파생 데이터 Selector는 `useMemo`와 순수 유틸로 전환했습니다.
- strangler 브리지 패턴으로 기존 인터페이스를 유지한 채 wave 0~5 단계로 나눠 점진적으로 이관했습니다.
- 라이브러리 마이그레이션 AI 스킬(migrate-lib)을 활용하고, 기능 단위로 변환 결과를 직접 검토했습니다.
- **Characterization Test로 기존 동작을 먼저 고정해 유닛 테스트를 49개에서 71개로 늘리고(신규 22개 100% 통과) 에러 경로 커버리지를 0건에서 9건으로 확보했습니다.**
- **consumer 21개 파일을 수정하지 않고 이관해 회귀 0건을 달성했고, QA에서 잡히지 않던 개발 미스 약 6건을 찾아냈습니다.**
- 검증 과정에서 나온 재조회 미동작, 로딩 상태, 지도 갱신 누락 회귀를 수정하고 기획 QA와 리그레션 테스트에 대응했습니다.

**모니터링과 개발 환경 개선**

- Datadog RUM을 신규 연동하고 Secrets Manager 기반 환경변수 체계를 확장했으며, 이후 원격 설정으로 샘플링을 제어하도록 적용했습니다.
- 테스트 목 환경을 axios-mock-adapter에서 MSW로 전환했습니다.
- trivy 보안 리포트를 기준으로 axios, uuid 등 라이브러리를 일괄 업데이트하고 Node 버전을 올렸습니다.

**지역설정제 (진행 중)**

- 지도 기반 지역 설정 화면, SM 목록, 차트 3종, 업무구간·그룹 설정, LNB 퍼블리싱을 개발했고 현재 API 연동을 진행하고 있습니다.

## 성장경험

---

1. 지도처럼 무거운 화면은 체감이 아니라 Heap Snapshot 같은 측정값으로 원인을 좁혀야 한다는 것을 경험했습니다.
2. 상태 관리 라이브러리 교체처럼 영향 범위가 큰 작업은 기존 동작을 테스트로 먼저 고정하고 작은 단위로 나눠 옮길 때 회귀 없이 끝낼 수 있다는 점을 확인했습니다.
3. 2022년 초기 구축에 참여했던 코드를 2026년에 다시 마이그레이션하며, 당시의 설계 결정이 시간이 지나 어떤 비용으로 돌아오는지 직접 확인할 수 있었습니다.

## 트러블 슈팅

---

**Situation**

1. 배정 현황을 지도에서 반복 조회할수록 화면이 느려지고 브라우저 메모리가 계속 늘어나는 현상이 있었습니다.

**Task**

1. 체감 문제가 아닌 수치로 원인을 확인하고, 운영 중인 화면에 영향 없이 구조를 바꿔야 했습니다.

**Action**

1. DevTools Heap Snapshot으로 조회를 5회 반복하며 detached DOM 개수를 측정해 지도 인스턴스가 조회마다 새로 생성되는 것이 원인임을 확인했습니다.
2. 지도 인스턴스를 싱글턴으로 관리하고 조회 시에는 마커와 레이어만 갱신하도록 변경했습니다.

**Result**

1. 조회당 약 290개씩 쌓이던 detached DOM이 0개로 줄어 반복 조회 시에도 메모리가 누적되지 않습니다.
2. 측정 방법을 팀에 공유해 이후 지도 화면 성능 이슈를 같은 기준으로 확인할 수 있게 했습니다.
