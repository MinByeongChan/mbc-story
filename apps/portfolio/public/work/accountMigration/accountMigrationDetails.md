## 개요

30만 회원 규모 통합회원의 Keycloak 의존 로그인·회원 화면을 React와 TypeScript 기반 인증 흐름으로 전환한 프로젝트입니다. 일반·SNS·중복 계정 로그인, 본인인증, 비밀번호 변경, reCAPTCHA 흐름을 포함하며, 2023년 Vue 3로 구축했던 서비스를 React로 다시 설계했습니다.

## 핵심 사례

### 템플릿이 쥐고 있던 인증 단계를 React 화면으로

기존에는 Keycloak FreeMarker 템플릿과 리다이렉트가 인증 단계를 제어해, 화면 분기와 오류 처리가 백엔드 템플릿에 묶여 있었습니다.

신규 API 응답을 기준으로 React 화면이 인증 단계를 직접 제어하도록 바꿨습니다. 단계별 상태는 Zustand로 관리하고 응답 스키마는 Zod로 검증해 서버 변경에 따른 화면 오류를 사전에 잡았습니다. 기존 리다이렉트와 신규 API의 오류 전달 방식을 비교해 토큰·인증 헤더·로그아웃의 책임 범위도 정리했습니다.

**일반·SNS·중복 계정 로그인, 본인인증, 비밀번호 변경, reCAPTCHA의 화면 분기와 오류 처리를 프론트엔드 로직으로 재구성해 백엔드 템플릿 의존도와 코드 복잡도를 낮췄습니다.**

### 예외 상태를 테스트와 문서로 고정하기

인증 서비스는 정상 플로우보다 예외 상태와 리다이렉트 복귀 처리가 품질을 좌우했습니다. 중복 계정 로그인 시 발생하던 400 에러를 응답별 프론트엔드 동작으로 정리하고, 카카오 로그인과 First Broker Login 예외를 포함한 SNS 로그인 에러 처리를 개발했습니다. 단계(step) 검증, redirect uri 쿼리 파라미터화, history 조작의 navigate 통일로 잘못된 단계 진입과 복귀 오류를 막았습니다.

**QA에서 발견된 예외 케이스는 Vitest와 Cypress 테스트로 전환해 회귀를 막았고,** 로그인 에러 케이스·SNS 로그인 에러 처리 가이드·테스트 케이스 문서를 남겨 전환 이후 운영 이슈를 빠르게 추적할 수 있게 했습니다. 30만 회원이 쓰는 화면을 바꿀 때는 테스트와 문서가 실질적인 안전장치가 된다는 것을 배웠습니다.
