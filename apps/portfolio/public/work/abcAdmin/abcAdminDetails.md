## 개요

미국 법인의 WMS 물류 흐름과 회계 전표·원장을 중심으로 주문(OMS), 테크니션 배정, 회계, 시스템 관리를 제어하는 통합 백오피스입니다. 1년간의 개발을 거쳐 서비스를 오픈하고 운영과 고도화를 이어갔으며, 본인 커밋 3,720건으로 가장 많이 기여한 프로젝트입니다.

## 핵심 사례

### 중복 API 호출을 정리해 화면 지연 67% 단축

주요 화면은 진입할 때 필요한 API를 한꺼번에 호출했고, 같은 데이터를 중복으로 요청하는 구간까지 있어 응답이 약 3초 걸렸습니다.

기획·BE와 함께 API 구조와 호출 순서를 다시 정리하고, 초기 진입에 필요한 호출과 사용자 액션 이후의 호출을 나눴습니다. TanStack Query의 Query Key, `staleTime`, `enabled` 조건을 정리해 중복 호출을 없앴고, Lazy loading과 Suspense, 컴포지션 패턴으로 첫 화면이 먼저 그려지도록 FCP도 개선했습니다.

**주요 화면 응답 기준으로 화면 지연을 67%(약 3초→1초) 단축했습니다.**

### 한 번의 수정이 246개 화면에: 공통 컴포넌트와 SNB 공통화

팀이 공동으로 구축한 공통 컴포넌트 78종 체계에 223커밋을 기여하며 버튼 그룹, 시간 선택, 대용량 다중 선택 등 신규 컴포넌트를 추가했습니다. 그중 테이블, 정의 목록, 입력 필드, 아코디언 등 핵심 컴포넌트 개선을 주도해 **테이블 개선 한 번이 246개 화면 파일에 일괄 반영되는 구조**를 만들었습니다. 앱 셸, 탭 메뉴, API 요청 공통 처리, 에러 화면 등 전역 레이아웃 개발도 주도했습니다.

화면마다 제각각이던 SNB 로직은 공통 훅으로 통합했습니다. **물류 도메인의 SNB 공통 훅 2종(각 8개 화면)과 메뉴별 필터를 저장하는 개인화 검색 훅(12개 화면)을 신규 개발했습니다.**

한 번의 수정이 수백 개 화면에 반영되는 만큼, 공통 코드는 영향 범위를 먼저 확인하고 신중하게 바꿔야 한다는 것을 배웠습니다.

## 그 외 작업

- WMS 출고 리뉴얼(배차), 창고이동, 실시간 재고 추적과 승인 프로세스 개발
- 창고·테크니션 재고실사 4단계 워크플로우와 재고 조정 화면 개발
- Shopify·OMS·AR 3단계 대사 화면, 전표·원장·합계잔액 시산표·반제 기능과 엑셀 다운로드 개발
- `react-big-calendar` 기반 테크니션 배정판, 잔여 시간 기반 자동 배정 결과 UI, 당일 긴급배정 개발
- 전자결재 1차 개발, Google Sheet 연동과 에러 로그 추적이 가능한 주문·물류 실시간 모니터링 대시보드 개발
- N:N 공통코드 관계 화면을 recoil selector 대신 커스텀 훅과 재귀 함수로 재설계해 리렌더링 성능 이슈 해결
- 50개 이상 화면의 공통 폼을 react-hook-form 기반 단일 템플릿으로 통합하고 FSD·Composition 아키텍처 적용
- `openapi-typescript`로 BE yaml에서 타입을 생성하고 FE·BE enum 코드를 맞춰 타입 작성 시간 단축
- 메뉴별 다국어 리소스 분리 로딩과 RBAC 기반 권한 처리 적용
- Sentry로 스테이징의 타입 에러와 비정상 API 호출을 검출해 Jira로 공유
- 코드 컨벤션 수립, 코드 오너와 PR 리뷰 도입, husky·commitlint로 컨벤션 위반 푸시 방지
- 기획 피드백용 Google Sheets 연동 창구와 기술 예제 페이지 운영
