## 개요

공부한 내용을 다시 정리하며 제 것으로 만드는 습관을 들이기 위해 만든 기술 블로그입니다. 티스토리, Gatsby 템플릿, GitHub Pages를 거쳐, 정해진 템플릿에서 벗어나 처음부터 직접 만들었습니다.

## 핵심 사례

### Next.js에서 SPA로, 그리고 다시 Next.js로

Next.js에 익숙하지 않던 시기에 유지보수가 어렵다는 이유로 블로그를 SPA로 옮겼습니다. 그러나 SPA에서는 SSR의 장점이던 SEO를 관리하기 어려웠고, 글을 HTTP 요청으로 가져오면서 이전에 없던 로딩 지연이 생겼습니다.

유지보수는 쉬워졌지만 성능상 이점이 없다고 판단해, 모노레포로 옮겨 Next.js로 다시 전환하기로 했습니다. 기술 선택은 익숙함보다 검색 노출과 콘텐츠 로딩 같은 서비스 특성을 기준으로 해야 한다는 것을 배웠습니다.

## 그 외 작업

- Markdown을 React 컴포넌트로 변환하는 렌더링 파이프라인 직접 구현
- Firebase 스토리지 기반 게시에서 로컬 콘텐츠 관리로 전환
