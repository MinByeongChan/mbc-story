# 통합배정판

2026.01 – 현재

## 서비스 내용

---

일 5K~10K뷰, 리마인드 알림톡 발송일 피크 28K~30K뷰 규모의 설치 업무 배정 플랫폼입니다. 신제품 배정 정책을 반영하고 Datadog RUM 기반 성능 모니터링 체계를 구축했습니다.

- 고객과 현장 작업자가 제품 설치 일정을 배정·변경하고 현황을 확인하는 화면을 제공합니다.
- 제품군마다 다른 배정 정책을 화면 흐름에 반영합니다.
- 운영 판단에 필요한 성능·전환 지표를 Datadog RUM 대시보드로 확인합니다.

## 기술스택

---

- React, TypeScript, TanStack Query, Datadog RUM, Vite, AWS CloudFront

## 개발내용

---

**신제품 배정 정책 반영**

- 에어컨, 소파, 모션 매트리스 등 신제품의 배정 정책을 반영한 운영 화면을 개발했습니다.
- 제품군별 정책 차이를 화면 분기와 검증 로직으로 정리해 운영자가 혼동 없이 배정할 수 있게 했습니다.

**배정판 기능 확장**

- 고객 직접 재배정 화면에 주소 단위로 주문을 묶는 groupOrderList UI와 로직을 개발했습니다.
- 설치일 변경 배정판에 AC_3PL 플로우와 반응형 툴팁을 개발하고 E2E 테스트로 흐름을 검증했습니다.
- 택배 출고 배정판(SHIPPING)을 리스트형 배정판으로 확장하고 M+2 말일 기준 일정 로직과 E2E 테스트를 작성했습니다.

**Datadog RUM 모니터링 체계 구축**

- Datadog RUM을 직접 연동하고 RUM-APM 분산 트레이싱(allowedTracingUrls)으로 화면 지연과 백엔드 API 구간을 함께 볼 수 있게 했습니다.
- 팝업 퍼널과 인앱브라우저(naver/kakao) 진입을 커스텀 이벤트로 트래킹하고, 세션 집계 기준을 정리해 지표 해석이 엇갈리지 않도록 했습니다.
- CloudFront에 둔 원격 설정(settings.json)으로 배포 없이 샘플링을 제어하고, RUM 초기화가 렌더링을 막지 않도록 논블로킹으로 처리했습니다.
- **설치일 변경 퍼널의 전환율 51.7%, 이탈률 30.6%를 측정하는 체계를 처음으로 구축했습니다.**

**알림톡 대량 발송 부하 대응**

- **리마인드 알림톡 일괄 발송 직후 FCP p90 8.7초, LCP p90 18.7초로 급등한 원인이 백엔드 API 포화(p90 17~28초)임을 RUM으로 입증했습니다.**
- 스켈레톤 UI, 비핵심 API의 렌더 논블로킹, 확정 버튼 중복 클릭 방지로 부하 구간의 사용자 경험을 보완했습니다.

## 성장경험

---

1. 트래픽이 큰 운영 화면은 기능 개발만큼 측정 기준을 먼저 세우는 것이 중요하다는 점을 확인했습니다.
2. 성능 문제가 생겼을 때 "프론트엔드 문제가 아니다"를 말로 주장하기보다 RUM과 APM 지표로 보여주는 것이 타 부서 협업을 훨씬 빠르게 만든다는 것을 경험했습니다.
3. 전환율과 이탈률을 직접 측정할 수 있게 되면서 화면 개선의 우선순위를 데이터로 판단하는 기준을 갖게 되었습니다.

## 트러블 슈팅

---

**Situation**

1. 리마인드 알림톡이 발송되는 날 오전 9시 직후, RUM 대시보드에서 FCP와 LCP가 급등하는 현상을 확인했습니다.
2. 발송 직후 10분간 4,735건이 진입했고, 이 구간의 FCP p90은 8.7초, LCP p90은 18.7초로 평시(FCP 1.1초, LCP 1.3초)보다 크게 늘어나 있었습니다.

**Task**

1. 지연의 원인이 프론트엔드 렌더링인지 백엔드 응답인지 수치로 구분해야 했습니다.
2. 원인이 화면 밖에 있더라도 부하 구간에서 사용자가 겪는 불편은 줄여야 했습니다.

**Action**

1. RUM-APM 분산 트레이싱으로 화면 지연 구간과 API 응답 시간을 연결해 보고, 발송 직후 `api-schedule` 백엔드의 API p90이 17~28초까지 늘어난 것을 확인했습니다.
2. 분석 결과를 리포트로 정리해 ERP 영업팀에 알림톡 발송을 분산(throttle)해 달라고 요청했습니다.
3. 병행해서 스켈레톤 UI를 적용하고, 비핵심 API가 렌더링을 막지 않도록 분리했으며, 응답 지연 중 확정 버튼이 중복 클릭되지 않도록 막았습니다.

**Result**

1. **RUM 지표로 프론트엔드 결함이 아닌 일괄 발송에 따른 백엔드 순간 포화임을 입증해, 원인 부서와 대응 방향을 빠르게 정리할 수 있었습니다.**
2. 부하 구간에서도 화면이 비어 보이거나 중복 확정이 발생하지 않도록 사용자 경험을 보완했습니다.
