## 개요

일 5K\~10K뷰 규모의 설치 업무 배정 플랫폼입니다. 고객과 현장 작업자가 제품 설치 일정을 배정·변경하는 화면을 개발하면서, 제품군별 배정 정책 반영과 Datadog RUM 기반 모니터링 체계 구축을 맡았습니다.

## 핵심 사례

### 알림톡 발송 직후 느려진 화면, 원인을 지표로 입증하기

리마인드 알림톡이 발송되는 날 오전 9시 직후 10분간 4,735건이 진입하면서 FCP p90이 평시 1.1초에서 8.7초로, LCP p90이 1.3초에서 18.7초로 늘어났습니다.

RUM-APM 분산 트레이싱으로 화면 지연과 API 응답 시간을 연결해 보니, 같은 구간에 일정 백엔드 API의 p90이 17\~28초까지 늘어나 있었습니다. 분석 결과를 리포트로 정리해 ERP 영업팀에 알림톡 발송 분산(throttle)을 요청했고, 병행해서 스켈레톤 UI 적용, 비핵심 API 논블로킹 분리, 확정 버튼 중복 클릭 방지로 부하 구간의 사용자 경험을 보완했습니다.

**프론트엔드 결함이 아닌 일괄 발송에 따른 백엔드 순간 포화임을 수치로 입증해, 원인 부서와 대응 방향을 빠르게 정리했습니다.** 성능 문제는 주장보다 지표로 보여줄 때 타 부서 협업이 빨라진다는 것을 배웠습니다.

### 흩어진 정책 문서를 검색 가능한 RAG로

배정 정책과 관련된 내용이 화면설계서, 회의록, 인수인계 문서에 흩어져 있었습니다. 이 문서들과 업무 용어를 ChromaDB에 벡터화하고 Claude Code가 MCP로 관련 문맥을 검색하도록 구성했습니다. 증분 동기화 오케스트레이터와 node-cron 기반 sync 데몬으로 문서 변경분이 자동 반영되게 했습니다.

처음에는 일부 청크가 임베딩 모델의 512토큰 한계를 넘어 잘린 채 저장되고, 바이너리 문서는 인덱싱 대상에서 빠져 있었습니다. 청크 크기와 분할 기준을 조정하고 바이너리 문서도 텍스트로 추출하도록 확장해 **512토큰 초과 청크를 0개로 만들고(85개 청크 실측 최대 369토큰), 인덱싱 대상을 179%(124건→346건) 늘렸습니다.**

배정 정책 변경 시 테스트 케이스 초안 작성과 인수인계 누락 확인에 활용했고, 검색 결과는 원문과 실제 서비스 동작을 기준으로 다시 검토했습니다. RAG의 품질은 모델보다 문서를 어떻게 자르고 어떤 문서를 넣는지에 좌우된다는 것을 경험했습니다.

## 그 외 작업

- 에어컨, 소파, 모션 매트리스 등 신제품 배정 정책을 화면 분기와 검증 로직으로 반영
- 고객 직접 재배정 화면에 주소 단위로 주문을 묶어 보여주는 UI와 로직 개발
- 설치일 변경 배정판 플로우, 택배 출고 배정판 리스트형 확장과 E2E 테스트 작성
- 팝업 퍼널·인앱브라우저(naver/kakao) 진입 트래킹으로 설치일 변경 퍼널 전환율 51.7%, 이탈률 30.6% 측정 체계 구축
- CloudFront에 둔 원격 설정 파일로 배포 없이 RUM 샘플링을 제어하고, RUM 초기화를 논블로킹으로 처리
