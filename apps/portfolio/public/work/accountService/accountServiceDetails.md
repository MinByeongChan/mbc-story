# 통합회원

2023.05 – 2024.04

URL: [https://www.coway.com/](https://www.coway.com/)

## 서비스 내용

---

레거시와 신규 서비스의 회원을 통합하는 30만 회원, DAU 약 5K 규모의 B2C 인증 플랫폼입니다.

- 코웨이 서비스인 코웨이몰, iocare(코웨이 IoT APP)에 대한 회원을 보유 및 통합하여 관리합니다.
- 회원가입, 계정찾기, 마이페이지, 회원 로그인 서비스 관련된 기본적인 기능을 제공합니다.
- 구 회원에게 통합회원으로 전환하는 기능을 제공합니다. (현재는 미지원)

## 기술스택

---

- Vue 3, TypeScript, Pinia, Vite, SCSS, Keycloak, Datadog, Jest, Storybook, Cypress, Docker, AWS (S3, CloudFront)

## 개발내용

---

**회원 서비스 페이지 개발**

- 마이페이지, 로그인, 계정 찾기, 회원가입 기능을 포함한 각 회원 서비스의 핵심 페이지를 개발했습니다.
- 코웨이몰과 ioCare 회원을 통합회원으로 전환하는 마이그레이션 화면을 개발하고 이름·포커스 등 필드 검증을 적용했습니다.
- 서비스(clientName)별 언어 고정, 푸터 약관 locale/국가코드 로직과 일본어·영어 번역을 적용했습니다.

**미국 신사업 프로젝트 초기 구축**

- 미국 신사업 프로젝트의 회원 서비스를 초기 구축하여 신규 시장 진출을 위한 기반을 마련했습니다.

**통합회원 연동 테스트 클라이언트(test-client) 개발**

- React/Vite 환경으로 통합회원 연동 테스트 클라이언트를 신규 개발했습니다.
- 클라이언트별 로그인, 회원가입, 아이디/비밀번호 찾기 시나리오를 실제 연동 방식대로 검증할 수 있는 도구를 만들어 연동 서비스의 사전 검증을 쉽게 했습니다.

**테스트 커버리지 강화**

- feature 별 유닛 테스트부터 통합 테스트까지 개발팀 내부에서 진행하여 버그 발생률을 최소화했습니다.
- QA에서 발생하는 버그들을 스크립트로 작성하여 재발하는 것을 방지했습니다.

**도메인 단위 구조 설계**

- DDD 패턴을 적용해 회원가입, OTP, 계정 모델과 Hook을 도메인 단위로 분리하여 신규 기능 추가 시 변경 영향 범위를 줄였습니다.

**웹 접근성과 호환성**

- WCAG 2.1 기준을 반영하고 iOS Safari, Android WebView, PC 브라우저별 예외 처리를 추가해 고객용 인증 화면의 접근성과 호환성을 개선했습니다.

**점유인증 및 본인인증 로직 개발**

- 점유인증, 본인인증 프로세스를 개발했습니다.
- NICE 본인인증을 위한 SDK를 개발하여 통합회원을 이용하는 서비스에 제공했습니다.
- npm 패키지를 통해 CDN으로 제공했습니다.

**배포 환경과 오류 추적**

- RND 환경 CI/CD를 구축하고 하드코딩된 값을 env 체계로 정리했습니다.
- Datadog으로 디바이스/OS/언어별 런타임 오류를 추적하고 각 서비스의 다국어 이슈를 신속하게 대응했습니다.
- QA에서 발견된 예외 케이스를 Jest/Cypress 테스트로 전환해 재발을 방지했습니다.

## 성장경험

---

1. 회원서비스를 경험할 수 있었습니다.
   - 서비스들이 글로벌 서비스를 진행하고 있어 v-validate를 활용하여 다국어와 입력 필드에 대한 검증하는 로직을 구성했습니다.
   - 본인인증 sdk를 관리하고 연동하는 개발을 수행했습니다.
2. keyCloak 프레임워크를 경험했습니다
   - 통합회원은 keyCloak 프레임워크를 사용하고 있어 이에 대한 이해도를 높일 수 있었고, keyCloak과 토큰을 주고 받으며 사이드 이펙에 대한 대응을 하여 서비스 품질을 향상 시켰습니다.
3. Vue 프레임워크 환경을 경험했습니다.
   - React 라이브러리만 사용하였던 커리어에서 처음으로 Vue의 기본적인 사용방법, 컴포넌트 구성방법, 도메인 구성방식 등을 고민하고 개발에 적용했습니다.
4. 연동하는 쪽의 입장에서 검증 도구를 만들었습니다.
   - test-client를 직접 만들며 통합회원을 붙이는 서비스가 어떤 순서로 로그인·가입 흐름을 호출하는지 이해했고, 연동 이슈를 QA 전에 재현할 수 있게 되었습니다.

## 트러블 슈팅

---

**Situation**

1. Vue2에서 Vue3로 업데이트하는 과정에서 이전에 잡히지 않던 이슈들이 QA에서 발견되었습니다.
2. Keycloak이 제공하는 리다이렉트 로그인 방식 때문에 토큰을 유지한 채 로컬에서 테스트하기 어려웠습니다.

**Task**

1. 해당 이슈들이 재발하지 않도록 테스트 코드를 작성하는 것이 좋다고 판단해, 레거시로 남아있던 e2e 테스트 코드를 다시 활성화했습니다.
2. 각 BE 서비스가 docker로 구성되어 있다는 점에 착안해, BE 이미지를 로컬에 올려 로그인 흐름 전체를 로컬에서 재현하는 테스트 환경을 구축하기로 했습니다.

**Action**

1. 유틸함수는 유닛 테스트로 검증하고, QA에서 발생하는 로그인 이슈와 api 관련 이슈는 cypress interceptor 기능으로 처리했습니다. store가 필요한 부분은 cypress에서 세팅하여 실제 브라우저 상황과 동일하게 만들어 테스트를 진행했습니다.
2. Keycloak과 BE 서비스 docker 이미지를 로컬에 띄워 리다이렉트 로그인과 토큰 발급을 로컬에서 그대로 재현하고, 그 위에서 회원가입, 계정찾기, 마이페이지 등 기능을 구현하고 확인했습니다.

**Result**

1. Vue3 코드 리팩터링으로 인한 이슈들은 해결되었고, 발생했던 이슈들을 테스트 코드에 케이스별로 남기게 되었습니다. 이 히스토리를 이용해 이후 발생하는 QA 이슈를 이전 버전과 비교하며 보다 확실하게 처리할 수 있었습니다.
2. BE, FE 개발이 끝난 뒤 QA에 들어가기 전, 각 개발자가 로컬 테스트 환경에서 피처 개발 건을 먼저 확인하고 반영하게 되어 운영 검증 면에서 안정성을 높였습니다.
