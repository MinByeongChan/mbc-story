## 개요

약 2만 명의 코디(영업직원)와 고객을 연결하는 비대면 매칭 플랫폼입니다. 고객이 매칭을 요청하면 코디에게 알림톡이 발송되고, 코디가 1분 안에 수락하면 매칭이 완료됩니다. Vue로 만들어진 서비스를 React로 전환하고 Datadog 모니터링 체계를 세웠습니다.

## 핵심 사례

### 매칭 타이머를 브라우저에서 서버 정책으로

매칭 상태를 브라우저에서 setTimeout으로 매초 확인하고 있어, 탭을 전환하거나 포커스를 잃으면 시간이 어긋나고 API도 불필요하게 자주 호출되었습니다.

브라우저 현재 시간을 기준으로 비교하는 dayjs 타이머로 바꾸고, 매칭 확인 주기는 BE가 내려주는 값으로 제어하도록 백엔드와 함께 정책을 바꿨습니다. 매칭 취소 API의 중복 호출을 막는 방어 로직을 넣고 matchingId도 로컬에서 제어하도록 전환했습니다.

**탭 전환 후에도 정확한 시간으로 매칭을 판단하게 되었고, 매칭 시간은 BE에서 DB 업데이트만으로 조정할 수 있어 이를 위한 비정기 배포가 줄었습니다.**

### 에러율 개선에서 시작한 모니터링 체계

SRI(에러율) 개선 활동에서 SRE·SLO·SLA를 조사하고 **Datadog RUM 모니터, 얼러트, 레이턴시 모니터링을 구축했습니다.** GitHub Actions로 앱 버전을 Datadog에 태깅해 배포 버전별로 에러와 성능을 볼 수 있게 했고, 비정상적인 API 호출은 백엔드 개발자와 함께 Datadog에서 추적했습니다.

모니터와 얼러트를 먼저 세워야 문제를 사용자보다 먼저 발견할 수 있다는 것을 배웠고, 이후 맡은 서비스마다 Datadog 모니터링을 구축하는 기준이 되었습니다.

## 그 외 작업

- Vue에서 React로 마이그레이션하며 중복 컴포넌트와 비즈니스 로직을 공통 컴포넌트·Custom Hook으로 재구성
- TanStack Query의 서버 상태와 Jotai의 화면 상태를 분리해 상태 불일치 구간 개선
- 운영 시간(08:00\~22:00) 외에도 신청할 수 있는 매칭 예약 기능 개발
- 영업 외 문의 약 13%라는 설문 결과를 근거로 제품 선택 기능 추가
- 매칭 신청 자격 조건 확인 화면, 관심 제품 등록 기능 개발과 월별 매칭 혜택 콘텐츠 운영
- 기획·마케팅팀과 GA360 이벤트에 제품 정보, 매칭 시도 횟수, 성공 페이지 진입률 연동
- Cypress E2E 테스트 작성, dev/stg 자동 배포와 prd workflow 배포로 CI/CD 고도화, 배포 노트 기반 버전 관리
- 외부 운영사로 GitHub 저장소·문서·운영 지식 인수인계
