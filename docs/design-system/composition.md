# 컴포지션(Composition) 가이드

UI를 **미리 완성된 큰 덩어리 하나**로만 제공하기보다, **작은 부품을 조합**해 화면을 만드는 방식을 기본으로 할 때 이 가이드를 따릅니다. Atomic Design의 “층”보다 **조합 책임이 누구에게 있는지**(라이브러리 vs 사용처)를 기준으로 설계합니다.

## 1. 정의

**컴포지션**은 상속 대신 **부품을 끼워 맞추어** UI를 구성하는 원칙입니다. React에서는 대표적으로 다음이 포함됩니다.

| 방식 | 설명 | 예시 |
| --- | --- | --- |
| **`children`** | 내용을 바깥에서 넘김 | `<Card><img /></Card>` |
| **명시적 슬롯 props** | 영역별로 노드 전달 | `header={...}`, `footer={...}` |
| **네임스페이스 조합** | 루트에 역할별 서브컴포넌트 부착 | `<Card><Card.Header />…</Card>` |
| **render props / 함수 자식** | 데이터·상태에 따라 그릴 내용을 위임 | `<List renderItem={…} />` |

한 가지만 고집할 필요 없이, **같은 디자인 단위** 안에서는 한 스타일로 통일하는 것을 권장합니다.

## 2. Atomic 대신 “조합”을 전면에 둘 때

| 기준 | 컴포지션에 유리한 경우 |
| --- | --- |
| 화면마다 **블록 순서·유무**가 다름 | 생략·순서 변경이 조합으로 드러남 |
| **콘텐츠**가 제품/팀마다 다름 | `children`·슬롯으로 열어 둠 |
| **variant 조합 폭발**을 막고 싶음 | 거대한 boolean 대신 “무엇을 넣을지”로 표현 |
| 디자인이 **슬롯 단위**로 스펙이 나뉨 | Figma와 코드의 영역 이름을 맞추기 쉬움 |

**단일 레이아웃·단일 변형**만 있으면 얇은 API(한 컴포넌트 + 소수 props)로 두고, 조합은 과하지 않게 유지합니다.

## 3. 디자인 (Figma) 정렬

- **부품 단위**: 카드·모달·섹션을 **프레임/컴포넌트**로 나누고, “헤더 / 본문 / 푸터”처럼 **역할 이름**을 코드·문서와 동일하게 씁니다.
- **슬롯**: 자유 배치 영역은 **placeholder** 또는 **instance swap**으로 표시하고, “코드에서는 `children` 또는 `footer` 슬롯”이라고 적습니다.
- **Variant**: 전체 톤은 상위(예: `size`, `emphasis`), 부위별 톤은 해당 부품의 variant로 둡니다.
- **토큰**: [토큰 전략](./token-strategy.md)에 맞춰 부품마다 시맨틱 토큰을 쓰고, 루트와 자식의 간격 규칙을 스펙으로 남깁니다.

## 4. 구현 (React) 규칙

### 4.1 경계

- **쉘(shell)**: 레이아웃·테마·공통 `aria`만 담당하는 얇은 래퍼.
- **내용**: 가능하면 **children·슬롯**으로 열고, 라이브러리가 문구까지 고정하지 않습니다.

### 4.2 상태

- 여러 부품이 **같은 값**을 쓰면 Context(또는 headless 라이브러리)로 묶고, **컨텍스트는 패키지 내부**에 둡니다.

### 4.3 props

- 루트: 전역 variant, 레이아웃, 제어 모드(value/onChange 등).
- 슬롯/자식: 해당 영역만의 props. **루트 전용 설정이 슬롯으로 새는지** 주기적으로 점검합니다.

### 4.4 스타일 (Tailwind / Panda)

- 조합 단위마다 `cva`/recipe를 쓰되, **이름 있는 토큰**만 참조합니다.

### 4.5 네임스페이스 API (선택)

`Parent.Child` 형태는 **컴포지션을 한 묶음으로 읽기 쉽게** 만드는 수단일 뿐, 필수는 아닙니다. 같은 목표를 `children` + 작은 컴포넌트 export로 달성해도 됩니다.

## 5. 접근성

- **패턴 단위 책임**: 모달·탭 등은 **한 경계**(쉘 또는 headless 루트)에서 `role`, 레이블 연결, 포커스 트랩을 완성합니다.
- **슬롯에 넣는 콘텐츠**는 사용처가 시맨틱·대비를 지키도록, DS 문서에 **권장 마크업**을 적습니다.
- 시각 순서와 **DOM/스크린 리더 순서**가 어긋나지 않게 조합합니다.

## 6. Storybook

- **부품 단독** 스토리: 디자인 QA용으로만 쓰고, **권장 문서**는 “조합 예시” 스토리에 둡니다.
- **조합 스토리**: 슬롯/children을 바꾼 여러 예시, 상태(열림·에러 등)별 예시.

## 7. 패턴과의 관계

재사용 가능한 **부품 조합**은 보통 **Components** 티어입니다. 자주 반복되는 **고정 조합**은 [컴포넌트·a11y](./components-and-a11y.md)의 **Patterns**로 올리고, 그 안에서도 역시 작은 컴포넌트를 조합해 구현합니다.
