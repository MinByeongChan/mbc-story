# 거버넌스: 기여·버전·레거시

## 1. 역할

| 역할 | 책임 (예시) |
| --- | --- |
| **Maintainer** | 토큰·컴포넌트 추가 승인, 릴리스 태깅 |
| **기여자** | RFC/PR 제출, 스토리·문서 동반 |
| **디자인** | Figma 라이브러리와 토큰 수치 정합 |

팀 규모에 맞게 1~2명 Maintainer로 시작해도 됩니다.

## 2. 기여 워크플로

1. **이슈 또는 RFC** — 새 컴포넌트·브레이킹 변경은 [컴포넌트 RFC 템플릿](./components-and-a11y.md#부록-컴포넌트-rfc-템플릿) 사용 권장.
2. **디자인 리뷰** (해당 시) — Figma와 토큰명 일치.
3. **PR** — 구현 + Storybook(또는 문서) + a11y 체크리스트 확인.
4. **머지** — Maintainer 승인 후 병합.

## 3. 버전 정책

- **`mbc-design-tokens`**: [시맨틱 버전](https://semver.org/lang/ko/)을 권장합니다.
  - **MAJOR**: 토큰 이름 제거·의미 변경으로 소비자가 깨짐
  - **MINOR**: 토큰 추가, 하위 호환 확장
  - **PATCH**: 문서·오타·동일 의미의 값 미세 조정(디자인 합의 하에)
- **앱 내부 컴포넌트**: 앱 `package.json` 버전 정책을 따릅니다. 공용 UI 패키지를 분리하면 그 패키지에 시맨틱 버전을 적용합니다.

브레이킹 변경 시 **마이그레이션 노트**를 `CHANGELOG.md` 또는 PR 본문에 남깁니다.

## 4. 레거시 점진 채택

| 규칙 | 설명 |
| --- | --- |
| **신규 우선** | 새 화면·새 파일은 `mbc-design-tokens` + 합의된 컴포넌트/패턴 사용 |
| **터치 시 개선** | 기존 파일을 수정할 때만 범위 내에서 토큰/컴포넌트로 치환 |
| **일괄 리라이트 금지 원칙** | 별도 에픽 없이 전 화면 갈아엎기는 하지 않음 |

필요 시 “레거시 허용 목록(예: 구 버튼 클래스)”을 한동안 두고, 신규 코드에서만 린트/리뷰로 차단합니다.

## 5. 품질 게이트 (선택)

- ESLint: `eslint-plugin-jsx-a11y` 등 (프로젝트 설정에 맞게)
- 시각 회귀: Chromatic 등 (Storybook 연동 시)
- PR 템플릿에 “DS 토큰/컴포넌트 사용 여부” 체크박스 추가
